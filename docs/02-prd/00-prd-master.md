## 1. 执行摘要（Executive Summary）

我们为中小制造企业（画像见 [02-market-personas](../01-strategy/02-market-personas.md)）构建 EvolverMon——开源 ERP+MES+WMS 一体化平台，解决其"订单-生产-库存全流程数据割裂在 Excel 与微信群、商业软件买不起、开源软件技术栈不匹配"的问题。产品以"一张工单跑通全厂"为最小闭环，采用多租户+多工厂架构支持集团化部署，Go+Gin 后端支撑车间级并发报工。商业上以免费软件获客、顾问服务变现。首年目标是 3 家种子工厂上线完整闭环、社区 1000 Star。

## 2. 问题陈述（Problem Statement）——全产品级

- **谁**：中小制造企业（10–500 人）的厂长、IT、仓管与班组长。
- **什么问题**：销售接单靠微信、生产进度靠喊、库存账实不符、质量无法追溯；现有工具（Excel/商业 ERP/开源 ERP）均不能同时满足"流程完整、便宜、可二开、中文原生"。
- **为什么痛**：交期失控直接丢单（生存问题）；月底盘点差异导致停产待料；客户验厂要求质量追溯（汽车/电子行业为强制门槛）。
- **证据**：见市场扫描 [01-open-source-landscape.md](../00-research/01-open-source-landscape.md) —— 最大竞争对手是"非消费"（Excel+微信群）；商业 ERP 报价 10 万+；开源方案无一匹配目标技术栈（GitHub API 实测）。

## 5. 全局业务流程（Solution Overview · 端到端）

```
┌─ ERP ─────────────────────────────────────────────┐
│ 销售订单 ──▶ MRP 运算 ──▶ 生产建议(工单) + 采购建议(请购单) │
└───────┬───────────────────┬────────────────────────┘
        ▼                   ▼
┌─ MES ───────────┐   ┌─ ERP-采购 ──────┐
│ 工单→派工→报工   │   │ 请购→采购订单     │
│   →质检→完工    │   │ →到货收货         │
└───┬────────┬────┘   └───┬─────────────┘
    ▼        ▼            ▼
┌─ WMS ──────────────────────────────────────────────┐
│ 领料出库(原材料)   成品/半成品入库   采购入库          │
│ 移库 / 盘点 / 批次追溯                               │
└───────┬────────────────────────────────────────────┘
        ▼
   销售出库 → 发货 → 订单关闭（闭环）
```

## 6. 成功指标（产品级 North Star + 分册指标）

- **北极星**：周活跃工单闭环率 = 每周"从创建到完工入库"走完全流程的工单占比（M1 目标：种子客户 ≥ 60%）
- 护栏指标：库存账实相符率（盘点差异数/盘点数，目标 <2%）；报工接口 P99 延迟 <300ms
- 分册指标见各分册第 6 章

## 7. 跨领域规范（Cross-Cutting Standards，所有分册必须遵守）

### 7.1 需求分级（MoSCoW）
- **M（Must）**：M1 闭环必需；**S（Should）**：M2；**C（Could）**：M3+；**W（Won't）**：本版不做（记入 Out of Scope）。
- 每条功能需求编号规则：`FR-<域>-<序号>`，如 `FR-WMS-012`；非功能 `NFR-<序号>`。

### 7.2 多租户与多工厂
1. 数据模型：所有业务表必含 `tenant_id`（租户=企业集团）；工厂级数据含 `factory_id`；仓库挂在工厂之下。
2. 隔离方式：共享库共享表 + 强制租户过滤（中间件注入查询上下文）；预留 PostgreSQL RLS 升级路径（NFR-部署）。
3. 用户可属于多工厂，登录后可切换"当前工厂"上下文（切换即重新过滤数据，不重登录）。

### 7.3 单据通用规范
1. 所有业务单据（订单/工单/出入库单等）共用规范字段：单号、状态、制单人、审核人、审核时间、备注、附件。
2. 单号规则：`<前缀>-<yyMMdd>-<流水号>`，前缀按单据类型全局配置（如 SO 销售订单、PO 采购订单、WO 工单、RCV 入库单、SHP 出库单、QC 质检单）。
3. 状态机通用模式：`草稿 → 已审核/已下达 → 执行中 → 部分完成 → 已完成 → 已关闭`；逆向：`作废`（仅草稿可删，其余只能作废+留痕）。状态迁移必须幂等且带乐观锁（version 字段）。
4. 单据打印：所有单据支持 PDF/热敏打印模板（M2）。

### 7.4 权限模型（RBAC + 数据范围）
- 功能权限：菜单/API 两级，绑定角色（平台分册详述）。
- 数据权限：`全部租户数据(仅超管) / 本租户 / 本工厂 / 本人` 四档，挂角色。

### 7.5 审计与追溯
- 所有写操作（增删改、审核、状态迁移）写 `audit_logs`：谁、何时、IP、租户/工厂、对象、before/after 摘要（脱敏）。
- 库存变动独立写 `stock_movements` 流水（只增不改），账实核对以流水为准。

### 7.6 国际化与本地化
- M1：中文（简体）单语言，但 i18n 框架从第一天内置（key 化文案）；M3 增加英文。
- 日期时区：服务器 UTC，展示随用户时区（默认 Asia/Shanghai）。

## 8. 全局不做清单

自建财务总账、薪酬考勤、CRM 线索管理、BI 自助分析平台、设备协议采集（M6 前）、原生 App、IoT 网关。

## 9. 依赖与风险（产品级）

- **依赖**：PostgreSQL 16+；对象存储（附件，S3 兼容/MinIO）；可选 Redis（M2 后引入缓存/队列）。
- 风险 TOP3：①业务深度不足（缓解：对照 Odoo 域模型季度审计）；②多租户数据泄漏（缓解：中间件强制过滤+测试门禁）；③社区冷启动失败（缓解：内容营销+种子客户共创）。
