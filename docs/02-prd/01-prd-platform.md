# PRD 分册一 · 平台底座（Platform Basement）

> 域代码 `PLT` · 覆盖：多租户/多工厂、组织与用户、RBAC、认证、菜单、审计、系统参数、通知
> 遵循总册 [00-prd-master.md](00-prd-master.md) 的跨领域规范（7.x）。

## 1. 执行摘要

平台底座是所有业务域的承载层：提供"企业（租户）→ 工厂 → 仓库"三级组织建模、用户与角色权限（RBAC+数据范围）、JWT 认证、操作审计、系统参数与单号规则配置。目标：让任何业务模块的开发不再关心"谁、在哪个厂、有什么权限"。

## 2. 问题陈述

- **谁**：租户管理员（厂长/IT）与所有业务用户。
- **什么**：多厂区企业需要"同一套系统、按厂隔离、老板可看全局"；现有开源项目要么单租户（若依系），要么租户模型僵硬（Odoo company 树）。
- **痛**：两个厂各装一套系统，数据无法汇总；权限粗放，仓管能看到采购价。
- **证据**：种子调研中"多工厂汇总"是厂长 TOP3 需求 🔶 Assumption。

## 3. 目标用户

主：租户管理员（老陈+小李合体角色）；次：全体登录用户（认证体验）。

## 4. 战略背景

多工厂多租户是本产品与若依系开源方案的核心差异之一，也是 F2 标准实施包（双工厂）的定价基础。

## 5. 方案概述

### 5.1 组织模型

```
Tenant 租户(集团)
 ├─ Factory 工厂A ─ Warehouse 仓A1/仓A2 …
 ├─ Factory 工厂B ─ Warehouse 仓B1 …
 └─ (跨厂调拨走物流单，见 WMS 分册)
```

### 5.2 认证与会话

- 登录：用户名/密码（bcrypt）；返回 access_token(2h) + refresh_token(7d)；支持后续扩展 OAuth2/LDAP（M5）。
- 上下文切换：登录后选择默认工厂；顶栏可切换工厂，切换后所有 API 自动按新上下文过滤。
- 登出 / 强制下线 / 连续失败 5 次锁定 15 分钟。

### 5.3 RBAC + 数据范围

- 角色 = 功能权限集合（API 权限点 × 菜单）+ 数据范围（本租户/本工厂/本人）。
- 预置角色：租户管理员、厂长（本租户全查）、计划员、采购员、车间主管、操作工、质检员、仓管员、财务（只读）。
- 用户可兼多角色；权限点命名 `<模块>:<资源>:<动作>`（如 `wms:stock:export`）。

## 6. 成功指标

- 管理员创建"一个新工厂+仓+5 个用户+角色"≤ 10 分钟（金路径录像验收）；
- 任何跨租户数据访问在自动化测试中 0 通过（安全门禁）；
- 登录接口 P99 < 100ms。

## 7. 功能需求

### 7.1 租户管理（FR-PLT-001~006）
- FR-PLT-001 [M] 超级管理员创建/停用租户（企业名、编码、联系人、有效期）。
- FR-PLT-002 [M] 租户内配置基础信息（logo、时区、启用的模块）。
- FR-PLT-003 [S] 租户级参数模板初始化（创建租户自动写入默认单号规则/参数）。
- FR-PLT-004 [M] 租户停用后其用户全部拒绝登录，数据只读保留。
- FR-PLT-005 [C] 租户配额（用户数/工厂数，托管版用）。
- FR-PLT-006 [W] 跨租户数据共享（明确不做）。

### 7.2 工厂与仓库（FR-PLT-010~014）
- FR-PLT-010 [M] 工厂 CRUD（编码、名称、地址、负责人、状态）。
- FR-PLT-011 [M] 仓库 CRUD（挂工厂；类型：原料仓/成品仓/半成品仓/不良品仓/在途仓）。
- FR-PLT-012 [M] 停用工厂前校验：存在未完结单据则禁止。
- FR-PLT-013 [S] 工厂级参数覆盖租户参数。
- FR-PLT-014 [C] 厂区地图/车间布局示意（Later）。

### 7.3 用户与角色（FR-PLT-020~028）
- FR-PLT-020 [M] 用户 CRUD（账号、姓名、手机、邮箱、所属工厂(多选)、状态）。
- FR-PLT-021 [M] 角色管理：角色 CRUD、权限点分配、数据范围设置。
- FR-PLT-022 [M] 用户-角色绑定（多角色）。
- FR-PLT-023 [M] 重置密码/首次登录强制改密。
- FR-PLT-024 [S] 用户组（按班组批量授权，MES 派工用）。
- FR-PLT-025 [S] 密码策略（长度/复杂度/有效期，租户参数）。
- FR-PLT-026 [M] 预置角色模板一键创建。
- FR-PLT-027 [C] 用户离职转交（业务单据批量移交）。
- FR-PLT-028 [W] 组织架构树复杂审批流（非本版）。

### 7.4 认证与会话（FR-PLT-030~035）
- FR-PLT-030 [M] 登录/登出/刷新令牌。
- FR-PLT-031 [M] 登录失败锁定（5 次锁 15 分钟）。
- FR-PLT-032 [M] 当前上下文（用户、权限点列表、当前工厂）查询接口。
- FR-PLT-033 [M] 工厂切换接口（重新绑定上下文）。
- FR-PLT-034 [S] 在线用户列表与强制下线（管理员）。
- FR-PLT-035 [C] OAuth2 / 企业微信扫码登录。

### 7.5 菜单与导航（FR-PLT-040~043）
- FR-PLT-040 [M] 菜单表（目录/页面/按钮三级），按角色过滤返回。
- FR-PLT-041 [M] 菜单与前端路由约定（前端按菜单 key 懒加载）。
- FR-PLT-042 [S] 租户级菜单定制（隐藏未用模块）。
- FR-PLT-043 [C] 自定义工作台卡片配置。

### 7.6 审计日志（FR-PLT-050~052）
- FR-PLT-050 [M] 写操作自动记录 audit_logs（见总册 7.5）。
- FR-PLT-051 [M] 审计查询界面（按人/时间/对象/动作过滤，仅管理员）。
- FR-PLT-052 [S] 敏感动作（删角色/改权限/改参数）单独标记。

### 7.7 系统参数与单号（FR-PLT-060~063）
- FR-PLT-060 [M] 参数管理（租户级 KV：允许负库存、默认时区、库存预占策略等）。
- FR-PLT-061 [M] 单号规则配置（前缀、日期格式、流水位数、是否含工厂码）。
- FR-PLT-062 [M] 单号生成服务（并发安全，数据库序列实现）。
- FR-PLT-063 [S] 参数变更审计联动。

### 7.8 通知中心（FR-PLT-070~072）
- FR-PLT-070 [S] 站内通知（工单超期、审批待办、盘点差异）。
- FR-PLT-071 [C] 邮件/企业微信 webhook 通道。
- FR-PLT-072 [W] 短信通道（不做，成本与合规）。

## 8. 用户故事（示例，验收标准 AC）

**US-PLT-01 创建双工厂**：作为租户管理员，我要在 10 分钟内建好"东莞厂+苏州厂"及各自仓库，以便种子客户演示。
- AC1 创建工厂必填编码/名称，编码租户内唯一；
- AC2 仓库必须挂在一个工厂下，仓库编码工厂内唯一；
- AC3 停用中的工厂不出现在业务单据的工厂下拉中。

**US-PLT-02 切换工厂上下文**：作为计划员，我在顶栏从东莞厂切到苏州厂，以便管理两地排产。
- AC1 切换后列表/看板数据立即只显示目标工厂；
- AC2 无该厂权限时切换被拒绝并提示；
- AC3 切换动作写入审计日志。

**US-PLT-03 最小权限仓管**：作为管理员，我给仓管员只配 WMS 模块+本厂数据范围，以便其看不到采购价与销售利润。
- AC1 仓管登录后菜单只出现 WMS 与工作台；
- AC2 直接调用 ERP 报价 API 返回 403；
- AC3 其查询任何列表不出现其他工厂数据。

## 9. 不做清单

组织架构审批工作流引擎（M5 评估轻量审批）、多租户联邦登录、SLA 级 API 网关。

## 10. 依赖与风险 / 开放问题

- 依赖：JWT 库、bcrypt；风险：权限点爆炸难维护 → 模块内资源×动作固定枚举生成。
- OQ：工厂切换是否影响进行中的草稿单据（当前假设：草稿跟随创建时的工厂，切换不影响已存草稿）🔶。
